# Automated Coding Multiagent Proctoring System

An enterprise-grade, modular backend system for proctoring online coding assessments. Designed for automated detection of candidate plagiarism, code collusion, variable-renaming evasion, identical hidden test bug patterns, and LLM AI-generated code usage (powered by the **Groq API** with model `openai/gpt-oss-120b`).

---

## 🌟 Key Features & Detection Modules

### 1. 🔍 Code Similarity Analysis (MOSS Approach)
- **Identifier Normalization**: Parses Python code (via AST and Tokenizer streams) and replaces variable names, function parameter names, and user identifiers with standard placeholders (`VAR_1`, `VAR_2`, etc.) while retaining language keywords and operators.
- **Dead Code & Obfuscation Stripping**: Removes comments, unused string docstrings, and dead assignment statements.
- **Winnowing Algorithm**: Extracts token n-grams ($k=6$), hashes them using BLAKE2b, and applies a sliding winnowing window ($w=4$) to generate MOSS structural fingerprints.
- **Jaccard Similarity**: Calculates structural overlap index between submission pairs and against AI reference baselines.

### 2. 🐛 Same Bug Analysis
- **Controlled Hidden Test Execution**: Safely executes candidate code against a suite of hidden test cases.
- **Error Taxonomy Classification**: Categorizes outputs into stable failure types (`WRONG_ANSWER`, `IndexError`, `ZeroDivisionError`, `TypeError`, `MISSING_ENTRYPOINT`).
- **Collusion Pattern Matching**: Constructs hashable failure pattern signatures. If Candidate A and Candidate B fail on identical hidden test cases with identical error classifications, the system flags potential peer collusion.

### 3. 🤖 AI-Generated Code Detection (Groq API)
- **Baseline Solution Generation**: Takes the DSA problem prompt and generates 3 independent reference AI solutions using Groq API (`openai/gpt-oss-120b`).
- **Forensic LLM Judge**: Uses a specialized Judge LLM prompt via Groq (`openai/gpt-oss-120b`) to evaluate candidate submissions against observable AI characteristics:
  - Canonical / textbook solution layouts standard in LLM outputs.
  - Absence of idiosyncratic human errors or informal coding quirks.
  - Standard type-hints and Google/Sphinx style docstrings typical of LLMs.
  - Structural alignment with generated AI baselines.

### 4. ⚖️ Risk Scoring & Threshold Flagging
- **Weighted Risk Aggregation**: Combines signals into a single bounded probability ($0.0$ to $1.0$):
  $$\text{Risk} = \frac{w_{\text{sim}} \cdot \text{CodeSim} + w_{\text{bug}} \cdot \text{BugSim} + w_{\text{ai}} \cdot (\text{AI\_Prob} \cdot \text{AI\_Conf})}{w_{\text{sim}} + w_{\text{bug}} + w_{\text{ai}}}$$
- **Threshold Flagging**: Candidates with a weighted risk score **$> 0.70$ ($70\%$)** are automatically flagged for manual human investigation (`FLAGGED_FOR_INVESTIGATION`).

## 📁 System Architecture & Directory Layout

```
week5/coding_proctor_system/
├── config.py             # Global configurations, weights, thresholds, paths, Groq settings
├── models.py             # Data models (Problem, TestCase, Submission, BugPattern, RiskResult, etc.)
├── similarity.py         # MOSS token normalization, Winnowing fingerprinting, Jaccard similarity
├── bug_detection.py      # Hidden test execution, failure pattern signatures, same-bug comparison
├── ai_detection.py       # Groq LLM API wrapper, baseline generation, Judge LLM AI forensics
├── risk_scoring.py       # Risk scoring aggregator, threshold logic, evidence reporting
├── proctor_engine.py     # Assessment engine orchestrating storage, evaluations, and reports
├── generate_samples.py   # Generator script for 4 DSA problems and realistic candidate submissions
├── main.py               # Main CLI application runner
├── README.md             # Complete technical specification and guide
└── data/                 # Data directory created dynamically at runtime
    ├── problems/         # DSA problem definitions & test case JSONs
    ├── submissions/      # Candidate source code stored as {problem_id}/{candidate_id}.py
    ├── ai_references/    # Cached AI baseline solutions generated by Groq
    └── reports/          # Evaluation report JSONs for flagged candidates
```

## ⚙️ Setup & Configuration

### Prerequisites
- Python 3.9+
- Groq API Key stored in your `.env` file.

### Environment Variable Setup
Ensure your `.env` file (at workspace root or in this directory) contains:

```env
GROQ_API_KEY=your_groq_api_key_here
GROQ_MODEL=openai/gpt-oss-120b
```

### Installation
Install required packages using `pip`:

```bash
pip install groq python-dotenv
```

To populate the sample DSA problems (4 problems), simulate candidate submissions (honest student, colluding cheater pair with renamed variables & identical bugs, and AI-assisted candidate), execute all detection tools, and generate risk scores:

## 💻 Modular Usage Example

You can also import and use individual modules directly in your backend system:

```python
from proctor_engine import OnlineCodingProctorEngine

# Initialize backend proctor engine
engine = OnlineCodingProctorEngine()

# Submit new candidate code for a problem
engine.submit_candidate_code(
    candidate_id="student_999",
    problem_id="prob_1_two_sum",
    code="def two_sum(nums, target): return []"
)

# Run full proctoring evaluation pipeline
risk_result = engine.evaluate_submission(
    candidate_id="student_999",
    problem_id="prob_1_two_sum"
)

print(f"Overall Risk Score: {risk_result.overall_risk:.2%}")
print(f"Flagged for Investigation: {risk_result.is_flagged}")
print(f"Recommendation: {risk_result.recommendation}")
```
